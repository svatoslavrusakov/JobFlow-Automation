# Вакансии из Telegram

## Подготовить вход

Первый этап читает **локальный JSON-экспорт одного публичного канала** из Telegram Desktop.
В меню канала выберите экспорт истории и формат JSON. Сохраните `result.json` внутри `data/`,
например в `data/telegram_export/`. Программа не входит в Telegram и не получает сообщения из сети.
Новое подключение и библиотеки для этого этапа не нужны.

Перед импортом откройте JSON и убедитесь, что `messages` содержит нужные посты.
Telegram описывает ограничения экспорта публичных каналов; полноту архива нужно проверять отдельно.
Основание формата: [официальная схема Telegram](https://core.telegram.org/import-export#chat),
[экспорт отдельного чата](https://telegram.org/blog/export-and-more).
Общий архив аккаунта и приватные каналы этот этап не поддерживает.

## Проверить через интерфейс

1. Откройте вкладку **Telegram**. В настройках проверьте «Папка сообщений Telegram»:
   по умолчанию `data/telegram`, отдельно от HTML сайтов компаний.
2. Поставьте лимит 2. Нажмите **«Сообщения из JSON»**, выберите экспорт и введите
   публичный адрес именно этого канала, например `https://t.me/channel_name`.
   Имя канала из экспорта не позволяет автоматически восстановить его публичный адрес.
3. В журнале должны появиться ссылки сохранённых постов. В каждой подпапке будут
   `page.html` и `source.json`. Здесь Google, ключ ИИ и резюме не используются.
   Лимит считает новые снимки; служебные сообщения и вложения без текста пропускаются.
4. Повторите импорт: старые снимки не заменяются. При лимите очередь продолжится с новых постов.
5. Включите VPN вручную, проверьте модель и ключ. Нажмите **«Распознать сообщения»**
   с лимитом 1: появится `vacancy.json`, в том же формате, что для сайтов компаний и hh.
   Проверьте название, компанию, описание, зарплату и контакты. Название канала не считается компанией.
6. Проверьте файл резюме и нажмите **«Подготовить письма»**: появится `draft.json`.
   Паузы и лимит ИИ общие с остальными сценариями. Готовые результаты пропускаются.
7. Выключите VPN вручную. Выберите **отдельный лист результатов** с базовыми колонками,
   `Сопроводительное`, `Подводные камни`, `Оценка ИИ`, `Требования к отклику`,
   `Контакты hr` и `Комментарий`. Нажмите **«Импортировать результаты»** с лимитом 1.
   Специальные требования дают `thinking`, иначе — `done`. Отправка работодателю остаётся ручной.

## Те же этапы в консоли

Выполняйте команды по отдельности из корня проекта. Замените адрес канала своим.
Между импортом сообщений, ИИ и импортом результатов переключайте VPN вручную.

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py import-telegram data\telegram_export\result.json --channel https://t.me/channel_name --limit 2
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py process-html --data-dir data\telegram --limit 1
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py draft-html --data-dir data\telegram --limit 1
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py import-results --data-dir data\telegram --limit 1
```

У импорта сообщений папка берётся из `telegram_dir`; её также можно задать через `--data-dir`.
У трёх общих команд без `--data-dir` используется папка сайтов компаний `html_dir`.
Интерфейс передаёт папку выбранного направления сам. Начальная строка и даты для этих этапов неприменимы.

## Ограничения

- Один текстовый пост обрабатывается как одна вакансия. Сводки с несколькими вакансиями,
  реклама и изображения без текста требуют отдельной обработки; модель не должна создавать из них одну вакансию.
- Ключ — полный URL поста, ID — `site:` и его SHA-256. Дубли определяются по ID/URL,
  а одинаковые вакансии в разных постах автоматически не объединяются.
- Пользователь задаёт соответствующий экспорту адрес канала. Его связь с числовым ID канала по сети не проверяется.
- Ошибочный ответ модели откладывает пост, как в [общем HTML-сценарии](company_vacancies.md#повторный-запуск-и-проверка).
  Для повторной попытки удалите файл ошибки нужного этапа в папке поста.
- Существующие снимки и JSON неизменяемы. После редактирования поста прежний результат
  нужно проверить и убрать вручную перед повторным распознаванием.
- Импорт в Google добавляет новые строки. Уже имеющиеся ID/URL пропускаются независимо от статуса.
  Исходные строки только со ссылками этот импорт не дополняет.
- Исходник и результаты хранятся в игнорируемой папке `data/`. Новые пути вне неё
  нужно отдельно исключать из Git. Реальный экспорт, ответы модели и запись Google ещё требуют ручного прогона.
