# Ключевые слова вакансий

[Краткий запуск](../README.md) · [Настройки ИИ](ai.md)

Этап читает описание вакансии и записывает ключевые слова в её строку основного листа.
Аналитику пользователь строит самостоятельно в Google Таблице. Служебные листы и счётчики не используются.

## Запуск

1. Добавьте колонку **`Ключевые слова`** в исходный лист. Также нужны `ID`, `Ссылка`, `Описание`.
   Порядок колонок не важен. В интерфейсе колонку можно добавить через «Колонки таблицы».
2. Сохраните модель и файл API-ключа в настройках. Chrome и резюме этому этапу не нужны;
   VPN переключается вручную.
3. В «Файлы и поиск» есть **«Промпт ключевых слов»**. По умолчанию используется
   `Scripts/ai/requirements_prompt.txt`; нужен один маркер `{{description}}`.
   Если выбран собственный промпт, обновите его ответ до формата `{"keywords": [...]}`.
4. На вкладке «hh → Этапы» задайте, например, лимит 3 и нажмите **«Ключевые слова»**.

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py requirements --limit 3
```

`--start-row 13` задаёт нижнюю границу строк. Статус отклика может быть любым и не меняется.
Письма, даты и другие поля также сохраняются. Заполняется только колонка `Ключевые слова`.

## Результат и повторный запуск

ИИ возвращает JSON `{"keywords": ["Python", "SQL"]}`. В ячейку записывается `Python; SQL`.
Повторы убираются; `Python`, `pyhton`, `Пайтон` объединяются в `Python` по словарю
в `Scripts/ai/requirements.py`. Неизвестные названия приводятся к нижнему регистру;
SQL и PostgreSQL остаются разными. Качество извлечения проверьте на первых нескольких вакансиях.

Заполненная ячейка, включая ручной текст и формулу, пропускается. Если компетенций нет,
записывается `—`. Для повторного анализа очистите ячейку: изменение описания или модели
само по себе не запускает переработку готовой строки.

Лимит ограничивает попытки анализа, включая неверные ответы ИИ. Заполненные ключевые слова
и пустые описания его не расходуют. Без явного лимита используется `ai_max_rows`. Паузы общие с ИИ:
`ai_pause_every` и `ai_pause_seconds`. Описания читаются порциями до 50 строк, но каждый запрос
к модели содержит только одну вакансию. Перед записью проверяются исходные поля и пустой результат.

При остановке или ошибке уже записанные слова остаются. При повторе готовые строки пропускаются;
неправильный ответ ИИ оставляет ячейку пустой. Не сортируйте лист во время работы этапа.
Служебные листы прежней версии автоматически не удаляются, но больше не используются.
Команда `competency-stats` и кнопка обновления статистики удалены.
