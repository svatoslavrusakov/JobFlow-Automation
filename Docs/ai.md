# ИИ, письма и черновики резюме

[Краткий запуск](../README.md) · [Карта кода](architecture.md)

Все команды выполняются из корня проекта.

## Подготовка письма через ИИ

Во вкладке «Настройки → Подключения» выберите модель Gemini и один источник ключа:

- «Ключ из файла» — укажите существующий текстовый файл с ключом.
- «Ввести новый ключ» — введите значение в скрытое поле; оно сохранится отдельно в `data/ai_key.txt`.
  Пустое поле сохраняет прежний ключ. Ключ не записывается в общий JSON или журнал.

Во вкладке «Файлы и поиск» выберите текст резюме и шаблон промпта в UTF-8. PDF/DOCX здесь
не читаются. Шаблон должен содержать ровно по одному маркеру `{{vacancy}}` и `{{resume}}`.

Основной файл — `data/settings.json`. Например, часть его параметров:

```json
{
  "spreadsheet": "HH_Vacancies_Analytics",
  "worksheet": "Тест_ai",
  "ai_provider": "gemini",
  "ai_model": "gemini-3.5-flash-lite",
  "ai_key_file": "data/ai_key.txt",
  "resume_file": "data/resume.txt",
  "prompt_file": "Scripts/ai/prompt.txt",
  "ai_max_rows": 50,
  "ai_pause_every": 3,
  "ai_pause_seconds": 30
}
```

Отсутствующие параметры берутся из стандартных значений. Старый `data/ai_settings.json` используется
только если общего файла ещё нет; после сохранения `data/settings.json` старый файл больше не читается.
При обновлении текущего проекта параметры ИИ перенесены, сами ключи и старый файл сохранены.

«Каталог моделей» читает список через API без генерации и передачи резюме. Наличие модели в каталоге
не подтверждает квоту. Кнопка «Проверить Google» получает список листов, «Проверить Chrome» проверяет
локальный порт без навигации. Для этих кнопок сначала сохраните настройки; VPN переключается вручную.

На 2026-11-13 бесплатный уровень предусмотрен для `gemini-3.5-flash-lite` и `gemini-3.8-flash`;
`gemini-3.1-pro-preview` требует платного API. Условия могут меняться:
[тарифы](https://aistudio.google.com/docs/pricing), [лимиты проекта](https://aistudio.google.com/rate-limit).
Диагностика HTTP 429 пока не менялась: журнал показывает только код.

Каждая вакансия передаётся отдельным запросом; история предыдущих вакансий не прикладывается.
`ai_max_rows` ограничивает очередь, `ai_pause_every` и `ai_pause_seconds` задают паузу.
Лимит на рабочей вкладке заменяет общий лимит ИИ только для одного запуска.

Команда `ai` читает только `new`, отправляет описание вакансии и текст резюме провайдеру, проверяет ответ
JSON и записывает письмо, подводные камни, оценку 0–100 и статус. Если ответ неверен, строка остаётся `new`.
Специальные требования работодателя (кодовое слово, вопрос, обязательный кейс, необычная инструкция)
сохраняются с цитатами в `Требования к отклику`; при их наличии устанавливается `thinking`, иначе `done`.
Обычный подводный камень сам по себе не меняет статус на `thinking`. Даже выполненное в письме специальное
требование требует ручного одобрения: проверьте письмо и поставьте `done`, если готовы отправить.
Проверка цитаты подтверждает её наличие в описании, но не гарантирует обнаружение моделью всех требований.
Существующие результаты и старые `done` автоматически не переоцениваются. `Комментарий` остаётся для заметок и анкет.
Если лимит задан в интерфейсе или через `--limit`, он заменяет `ai_max_rows` только на текущий запуск.
Этот этап не отправляет отклик на hh. Перед передачей личных данных проверьте условия своего тарифа AI Studio.

## Ключевые слова вакансий

Отдельный этап **«Ключевые слова»** извлекает компетенции без резюме и заполняет одноимённую
колонку в исходной строке. Модель, ключ и паузы общие; промпт отдельный.
Аналитика выполняется пользователем в таблице. [Запуск и повторная обработка](competencies.md).

## Черновик резюме под вакансию и экспорт DOCX

В окне письма нажмите **«Резюме → JSON»**. Используются текущие настройки модели, ключа
и исходного резюме (UTF-8 TXT или Markdown). VPN включается вручную перед запросом к ИИ.
Входом служат данные вакансии, показанные в открытом окне. Если их изменили в таблице,
сначала перечитайте строку.

Отдельный промпт: [Scripts/ai/resume_prompt.txt](../Scripts/ai/resume_prompt.txt).
Он задаёт акценты под вакансию и требует сохранить исходные факты.
[JSON-схема](https://aistudio.google.com/docs/structured-output) передаётся через общий запрос Gemini;
прежний формат сопроводительных писем сохранён.

Результат находится в `data/resume_drafts/<ID>_<суффикс>/resume.json`.
Путь отображается в окне; каждый запуск создаёт новый вариант.
В документе есть:

- `resume.sections` — разделы резюме, готовые формулировки и `source_quotes` из исходника.
- `resume.changes` — пояснения к изменениям.
- `resume.questions` — вопросы для ручной проверки.
- `review_status: needs_review` — обязательная ручная проверка, заданная программой.
- Снимок вакансии, модель, время и хеш прочитанного текста исходного резюме.

Проверка отклоняет цитаты, которых нет в исходном резюме. Она не доказывает смысловую точность
переформулированного текста и полноту документа: вручную сверяйте даты, компании, навыки,
результаты и возможные пропуски. Откройте JSON в редакторе и просмотрите все разделы и вопросы.

Этот этап сохраняет локальный черновик. Письмо и статус в Google не меняются.
Экран сравнения резюме, отдельные поля мест работы, точный шаблон и PDF остаются частями пункта 23.
Файлы `data/resume_drafts` исключены из Git.

## Сохранить DOCX-черновик

Обновите зависимости на компьютере, где нужен экспорт:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ai.txt
```

Создайте черновик через **«Резюме → JSON»** или выберите сохранённый файл кнопкой **«Открыть JSON»**.
После успешной проверки становится доступна кнопка **«Сохранить DOCX»**. Открытие JSON работает локально.
Храните черновики в `data/resume_drafts`: экспорт создаётся рядом с выбранным JSON, а эта папка исключена из Git.
Экспорт локальный, повторного запроса к ИИ нет. Документ создаётся рядом с JSON под именем
`resume_draft_<суффикс>.docx`; повторные экспорты сохраняются отдельными файлами.

При открытии и перед экспортом проверяются JSON, цитаты и хеш текущего текстового исходника.
В интерфейсе также сверяются ID, ссылка, заголовок, компания, зарплата и описание вакансии;
изменение статуса или письма не мешает использовать тот же черновик.
Если исходное резюме изменилось, выберите соответствующий файл в настройках или создайте новый черновик.
В DOCX выводится текст разделов. Цитаты, вопросы и объяснения изменений остаются в JSON.
Документ не получает автоматического одобрения, а `review_status` остаётся `needs_review`.

Базовое оформление: A4, одна колонка, поля 2 см, Arial, стандартные заголовки и списки.
Откройте файл в Word или LibreOffice и проверьте содержание, переносы страниц и контакты.
Это DOCX-черновик, а не точное воспроизведение ещё не полученного шаблона.

Интерфейс запоминает путь JSON в текущем окне письма. После закрытия выберите его снова через
«Открыть JSON»; новая генерация не требуется. Отмена выбора сохраняет прежний путь, неверный файл
не разрешает экспорт. Путь также сбрасывается при изменении исходных полей вакансии и начале
новой генерации. Исходные файлы на диске сохраняются; правки письма при открытии JSON остаются в окне.

[Схема подготовки резюме](../Diagrams/resume_documents.md) показывает ручную проверку и этапы экспорта.
