# Подготовка компьютера и проверка проекта

[Краткий запуск](../README.md) · [Карта кода](architecture.md)

Все команды выполняются из корня проекта.

## Подготовка компьютера

Команды ниже выполняются в PowerShell **из корня проекта**. Нужен Python 3.10 или новее; рабочие версии
проекта — 3.11 и 3.13.

Если виртуального окружения ещё нет, создайте его и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Далее запускайте `.\.venv\Scripts\python.exe` напрямую. Активировать окружение в PowerShell не требуется.
Для графического интерфейса устанавливайте `requirements.txt`: он включает Selenium, `gspread`
и зависимости ИИ. Минимального `requirements-ai.txt` достаточно для консольного ИИ-этапа и экспорта
документов; GUI без Selenium пока не запускается. В набор входит `python-docx` для экспорта резюме;
лицензия или установка Word для создания файла не требуются.

### Таблица и локальные файлы

1. Положите `credentials.json` для доступа к Google Таблице в корень проекта. Файл исключён из Git. При первом
   подключении откройте доступ к таблице для сервисного аккаунта из этого файла.
2. В окне «Настройки» выберите файл доступа Google, документ по имени/ID/ссылке и лист по умолчанию.
   Лист создайте заранее. Дубли проверяются в пределах выбранного листа.
3. В первой строке листа укажите обязательные заголовки hh: `ID`, `Компания`, `Компания ссылка`,
   `Заголовок`, `Зарплата`, `Описание`, `Ссылка`, `Статус`. Порядок не важен, но названия должны
   совпадать при начальной настройке. Позднее названия можно менять во вкладке «Колонки таблицы»:
   назначение сохраняется в примечании заголовка. Пустые позиции допустимы, дубли назначений запрещены.
4. Для остальных этапов добавьте нужные колонки: `Комментарий` и `Сопроводительное` для отправки,
   `Подводные камни`, `Оценка ИИ` и `Требования к отклику` для ИИ, `Дата проверки` для проверки ответов.
   Для этапа «Ключевые слова» нужна одноимённая колонка. Необязательная `Дата и время добавления` заполняется при успешном сохранении вакансии; импорт одной ссылки оставляет её
   пустой.

`data/`, `Examples/` и `Test/` исключены из Git. После клонирования проекта локальные ключи, резюме, ссылки
поиска, сохранённые HTML и звук переносятся отдельно. Общие локальные параметры находятся в
`data/settings.json`; ключи хранятся отдельными файлами, в JSON сохраняются только пути к ним.
`core/settings_defaults.py` содержит стандартные значения, `core/config.py` читает общие настройки для обработчиков.

### Chrome для существующих команд Selenium

Перед работой с hh выключите VPN вручную. Откройте отдельный Chrome из PowerShell:

```powershell
& "C:\Program Files (x86)\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9223 --user-data-dir="$env:LOCALAPPDATA\Auto_hh\ChromeTest" "https://hh.ru"
```

Если Chrome установлен в другом месте, измените путь к `chrome.exe`. В открывшемся окне войдите в нужный
аккаунт hh. Профиль `ChromeTest` сохраняется между запусками. В настройках адрес Chrome
должен совпадать с портом команды: `127.0.0.1:9223`. Кнопка «Открыть Chrome» использует выбранные
программу, порт и папку профиля. Галочка на `chrome://inspect` для этого способа не
нужна. Не переключайте вкладки управляемого Chrome во время работы скрипта.

При подключении журнал отдельно показывает проверку порта Chrome, выбор драйвера и результат подключения.
Готовый ChromeDriver подходящей сборки берётся из кэша без сетевого обновления. Если его нет, Selenium
подбирает драйвер с тайм-аутом сетевых запросов 20 секунд. При закрытом порту запуск сообщает ошибку
после короткой проверки. Тайм-ауты задаются в «Настройки → Паузы и ожидания».

## Капча, паузы и остановка

Если hh показывает капчу, `Scripts/hh/captcha.py` проверяет **видимое** поле ввода перед чтением и важными
кликами. `data/Duck.mp3` повторяется, пока вы вручную не пройдёте проверку в Chrome. Затем текущий запуск
завершается, не меняя статус этой строки. `Ctrl+C` прекращает ожидание. Если MP3 отсутствует или не
воспроизводится, программа сообщает об этом и всё равно останавливается. На другом ПК скопируйте `Duck.mp3` в
`data/` отдельно.

Интервалы задаются в «Настройки → Паузы и ожидания» и сохраняются в общем JSON.
Стандартные интервалы и пояснения находятся в `core/settings_defaults.py`; обработчики получают
прежние имена `DELAY_*` через `core/config.py`. Тайм-аут ограничивает ожидание готовности,
а пауза выполняется независимо от неё. Основные паузы показываются в консоли; короткие паузы при вводе письма не печатаются. Эти
паузы не гарантируют отсутствие проверки hh.

Коды завершения: `0` — этап завершён без ошибок, `1` — ошибка или остановка для проверки, `130` — остановка
через `Ctrl+C`. Если результат записи в Google Таблицу неясен после потери связи, проверьте строку вручную
перед повтором.

## Как проверить изменения

Используйте отдельный тестовый лист в той же Google Таблице: выберите его в окне или настройках и добавьте
обязательные заголовки. `credentials.json` менять не требуется. Перед запуском можно проверить отбор
через «Показать очередь»: лист должен остаться неизменным, Chrome для просмотра не нужен.
Короткая проверка по этапам:

1. `import-html`: импортируйте сохранённую выдачу, убедитесь, что появились только ID и ссылки. При повторе
   новые строки не должны добавиться. Вместе с ID и ссылкой импортируются название и компания;
   для нескольких выдач используется `import-folder`.
2. `fill` или `search`: убедитесь, что заполнились заголовок, описание, компания и доступная зарплата, а
   статус стал `new`.
3. `ai`: сначала задайте лимит 1. Проверьте письмо, риски, оценку и цитаты требований.
   Без специальных требований ожидается `done`, с ними — `thinking`; старые результаты не меняются.
4. `send`: подготовьте одну подходящую вакансию и проверьте письмо перед запуском. **Команда реально отправит
   отклик.** После подтверждения ожидается `wait`. В журнале должно быть ожидание «без перезагрузки»;
   после финального клика страница не загружается повторно. Если hh покажет окно города поверх
   «Резюме доставлено», результат должен остаться `wait`. Настоящая анкета даёт `form` без заполнения.
5. `check`: проверьте `wait` и обновление колонки `Дата проверки`; отдельно проверьте обе границы
   диапазона и включение строк без даты. Фильтр дат действует только на этот этап.
6. Параметры запуска: начните с заданной строки с лимитом 1; убедитесь, что неподходящие статусы
   не обрабатываются. При проверке отправки учитывайте [ограничения отправки](../Docs/stages.md#известные-ограничения-отправки).

Детальные локальные заметки могут лежать в `Test/`, но эта папка исключена из Git и не появится после
клонирования. [Схема процессов hh](../Diagrams/hh_processes.md) и [схема отправки](../Diagrams/hh_applications.md)
находятся в репозитории.
