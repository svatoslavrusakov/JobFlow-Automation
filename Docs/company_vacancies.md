# Вакансии сайтов работодателей

[Краткий запуск](../README.md) · [Схема](../Diagrams/company_vacancies.md)

## Сохранить и распознать страницы

1. В таблице добавьте полные URL в «Ссылка», оставьте «Статус» пустым.
2. С выключенным VPN откройте Chrome программы. Запустите «Сохранить HTML сайтов»
   или `run.py collect-html`. В папке HTML-снимков появятся `page.html` и `source.json`.
3. Завершите сбор, вручную включите VPN. Выберите модель, файл ключа и «Промпт HTML сайтов»
   в настройках. Резюме распознаванию не требуется.
4. Задайте лимит 1 и нажмите «Распознать HTML сайтов». Либо выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py process-html --limit 1
```

Используется «Папка HTML-снимков» (`html_dir`), по умолчанию `data/vacancies`.
Для обработки другой папки у `process-html`, `draft-html`, `import-results` есть `--data-dir`.
Эти же обработчики используются на вкладке [Telegram](telegram.md) с отдельной папкой сообщений.
Снимки перебираются по имени папки. Начальная строка и даты здесь неприменимы;
CLI отклоняет их, интерфейс читает только лимит. Без лимита используется `ai_max_rows`.
Один запрос содержит одну страницу. Паузы задают `ai_pause_every` и `ai_pause_seconds`.
Промпт по умолчанию — `Scripts/ai/html_prompt.txt`; нужны маркеры `{{html}}` и `{{url}}`.

## Единый формат результата

В каждой папке снимка сохраняется `vacancy.json`: плоский словарь с теми же названиями
полей и строковыми значениями, которые возвращает чтение вакансии hh.

```json
{
  "ID": "site:<SHA-256 полного URL>",
  "Компания": "Компания",
  "Компания ссылка": "https://example.org/about",
  "Заголовок": "Аналитик данных",
  "Зарплата": "от 100 000 ₽",
  "Описание": "Обязанности, требования, условия и способ отклика",
  "Ссылка": "https://example.org/jobs?id=123#details"
}
```

ID и исходную ссылку назначает программа. Числовые ID hh остаются прежними.
Неизвестная компания, её ссылка и зарплата сохраняются пустыми строками.
При наличии добавляются существующие поля `Контакты hr` и `Комментарий` (например, ссылка на анкету).
Названия, описание, ID и ссылка обязательны. Статус, даты, письмо и подводные камни этот этап не создаёт.

Проверка JSON отсеивает неправильную структуру и пустое описание, но не доказывает точность
извлечения. Сверьте результат с исходной страницей: компанию, зарплату, полноту требований и контакты.
В модель передаётся полный сохранённый HTML; скрипт не обрезает и не переписывает страницу.

## Подготовить письмо по резюме

После распознавания, пока VPN включён, укажите в настройках непустой файл резюме
и обычный промпт письма (`resume_file`, `prompt_file`). На вкладке «Сайты компаний»
задайте лимит 1 и нажмите **«Подготовить письма сайтов»**. Команда для консоли:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py draft-html --limit 1
```

Обходится та же папка снимков; папки без `vacancy.json` пропускаются. Один запрос — одна вакансия
и ваше резюме. Применяются те же настройки модели и пауз, что у писем hh. В `draft.json` сохраняются:

- `vacancy` — исходные поля конкретной вакансии;
- `result` — общий с hh ответ: `cover_letter`, `pitfalls`, `fit_score`, `application_checks`;
- `model`, `saved_at` — модель и локальное время подготовки.

Файл резюме и ключ в результат не копируются. Перед сохранением повторно сверяются снимок и вакансия.
Специальные требования с цитатами остаются в `application_checks`: их нужно проверить вручную.
Статусы Google Таблицы здесь не меняются. При импорте специальные требования дают
`thinking`, отсутствие требований — `done` с сохранённым письмом.

Откройте `draft.json`, проверьте письмо, риски, оценку и полноту требований. Повторный запуск
должен пропустить готовые документы. Изменение резюме, модели или промпта само по себе не заменяет
готовые письма: для новой генерации удалите только выбранный `draft.json` вручную.
Если меняете `vacancy.json`, старое письмо также требует ручного решения; оно не перезаписывается.

## Импортировать готовые результаты

1. Завершите ИИ-этапы, вручную выключите VPN.
2. Создайте отдельный лист результатов в том же документе Google. Скопируйте шапку основного листа:
   нужны базовые колонки вакансии и `Сопроводительное`, `Подводные камни`, `Оценка ИИ`,
   `Требования к отклику`. Если извлечены контакты или анкета, нужны также `Контакты hr` и `Комментарий`.
   Колонка `Дата и время добавления` необязательна; при наличии получает время импорта.
3. На вкладке «Сайты компаний» укажите имя этого листа и лимит 1.
4. Нажмите **«Импортировать результаты»**. Либо выполните команду, предварительно выбрав
   целевой лист в сохранённых настройках:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py import-results --limit 1
```

Импорт читает ту же папку HTML-снимков. API-ключ ИИ, резюме и Chrome ему не нужны.
Проверяются исходник, `vacancy.json`, письмо, оценка и цитаты. Неготовые пары пропускаются;
повреждённые сообщаются как ошибки. В строке сохраняются данные вакансии, письмо и результаты анализа.
Специальные требования дают `thinking`, иначе — `done`; отклик при импорте не отправляется.

Строки добавляются партиями до 50 через существующий `sheets.save_vacancies` с `RAW`.
Дубли проверяются по ID и полному URL независимо от статуса. Существующие записи не обновляются:
на исходном листе со ссылками они будут пропущены, поэтому используйте отдельный лист результатов.
Лимит считает только новые записи; пустой лимит импортирует все новые готовые результаты.
Пауза между партиями — общая `DELAY_IMPORT_BATCH`. Шапка и ID/ссылки читаются один раз за запуск.

Повторите импорт: уже записанные вакансии должны быть пропущены, ручные правки сохранены.
Одновременные запуски не предусмотрены. После обрыва записи проверьте последнюю партию:
программа не повторяет сетевую ошибку с неизвестным результатом, но повторяет явный отказ 429.

## Повторный запуск и проверка

- Запустите сначала на одном снимке и проверьте `vacancy.json` в его папке.
- Повторите: готовый результат должен быть пропущен без запроса к ИИ.
- Для повторного распознавания вручную удалите только нужный `vacancy.json`.
  Исходные `page.html` и `source.json` сохраните. Если уже есть `draft.json`,
  сохраните его отдельно и удалите из папки перед новым письмом.
- Повреждённые снимки и JSON сообщаются как ошибки, существующие файлы не заменяются.
  Неверный ответ модели помечается файлом `process-html.error.json` или `draft-html.error.json`.
  Снимок откладывается: следующие запуски пропускают его без запроса к ИИ и расхода лимита.
  Изучите сообщение в этом файле, исправьте вход или промпт и удалите отметку для явной повторной попытки.
- Ошибка API останавливает этап. Сохранённые результаты остаются для следующего запуска.

Все файлы остаются локально в исключённой из Git папке `data/`.
Браузер и Google на двух ИИ-этапах не используются. Адаптация резюме внешней вакансии
и автоматическая отправка ещё не реализованы; импорт готовых результатов доступен. После завершения работы с ИИ VPN выключается вручную.
