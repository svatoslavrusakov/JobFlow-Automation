# Экранный режим

[Краткий запуск](../README.md) · [Карта кода](architecture.md)

Все команды выполняются из корня проекта.

## Экранный режим в обычном Chrome

Это отдельная команда `desktop-send` и вкладка **«Экранный режим»**. Прежний `send` работает через
Selenium, как раньше. Экранному режиму нужен обычный Chrome с уже открытым аккаунтом hh;
порт отладки, ChromeDriver, JavaScript и чтение DOM не используются. Мышью управляет PyAutoGUI,
русский текст вводится через pynput. [Документация PyAutoGUI](https://pyautogui.readthedocs.io/en/latest/quickstart.html).

Дополнительные библиотеки установите отдельно; старые команды их не требуют:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
```

Сначала сохраните образцы во вкладке «Экранный режим». Откройте в Chrome обычное окно отклика,
раскройте пустое поле письма. Выберите элемент в списке, нажмите «Добавить образец», переключитесь
в Chrome до окончания отсчёта и выделите нужный фрагмент на полученном снимке.

Для первой пробы нужны **область окна отклика целиком, заголовок окна, выбранное резюме и пустое поле письма**.
Образец поля выделяйте так, чтобы его центр попадал в поле ввода. Все образцы создавайте при одном
размере Chrome и неизменном масштабе Windows/страницы, на основном мониторе.

Каждое действие теперь проходит одну последовательность: найти прямоугольник на свежем снимке →
навести курсор → снова снять экран и подтвердить тот же элемент под курсором → один клик.
При смещении Chrome, курсора или исчезновении элемента клик отменяется. Координаты не переносятся
между переходами и раскрытием окна. Если кнопка меняет оформление при наведении, добавьте второй
образец того же элемента в состоянии наведения. Однотонные фрагменты отклоняются при сохранении и загрузке.

На вкладке «hh → Этапы» выберите тестовый лист и начальную строку с `done` и непустым письмом.
Вручную откройте окно отклика **именно этой вакансии**, оставив поле пустым. Запустите
«Проба: заполнить открытое окно» и вернитесь в Chrome до окончания отсчёта. Эквивалент в консоли:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py desktop-send --start-row 13 --limit 1
```

**Без `--submit` программа заполняет только одно уже открытое окно.** Она не переходит по ссылке,
не нажимает первичную или финальную кнопку отклика и не меняет таблицу. Если поле скрыто,
можно отдельно сохранить образец «Добавить сопроводительное». После пробы проверьте письмо
и закройте окно вручную без отправки.

Автоматический проход по очереди включается отдельно:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py desktop-send --submit --start-row 13 --limit 5
```

**Эта команда отправляет настоящие отклики.** В интерфейсе ей соответствует «Отправлять по экрану…»
с подтверждением. Кроме образцов для пробы обязательны: первичная кнопка, активная финальная кнопка,
маркер анкеты, маркер капчи и хотя бы один маркер уже отправленного отклика/доставки.
Активную финальную кнопку снимайте с временным текстом письма, не нажимая её; затем очистите поле.
Пока обязательные образцы не сохранены, автоматический режим не запускается.
Архив, недоступность, отказ и приглашение распознаются при наличии соответствующих образцов.
Можно добавить несколько вариантов одного элемента. Неизвестный экран останавливает очередь.

Очередь `done`, проверка дублей, перечитывание строки перед отправкой и запись результата общие
с Selenium. Неверная ссылка учитывается как ошибка строки; остальные ссылки продолжают
обрабатываться, а итоговый код запуска сообщает о наличии ошибок.
Лимит считает только подтверждённые новые отправки; уже отправленные вакансии
синхронизируются без повторного отклика. Распознанная анкета даёт `form` и адрес в комментарии.
Известные признаки анкеты/капчи проверяются до ввода, периодически во время печати и после неё.
Проверка состояния страницы назначается примерно каждые 0,5 секунды и перед переводом строки;
время распознавания увеличивает фактический интервал. Между проверками может успеть ввестись несколько
символов. Новые разновидности анкет могут потребовать дополнительных образцов.
Перед финальным кликом письмо повторно сверяется с таблицей; потеря фокуса отменяет отправку.
После финального клика статус меняется только по знакомому подтверждению; повторного клика нет.
Если после первичного клика hh сразу подтвердит отклик без окна письма, сохраняется `wait`
и очередь останавливается для ручной проверки письма. При неизвестном результате или капче `done` остаётся — перед перезапуском проверьте отклик вручную.

Паузы между вакансиями и ожидания результата берутся из общих настроек. Интервал ввода символов,
точность сопоставления и отсчёт перед стартом задаются на новой вкладке. После отсчёта Chrome должен
оставаться активным и доступным на экране: не переключайте его вкладки и не пользуйтесь мышью/клавиатурой
параллельно. Смена активного окна или размера Chrome останавливает запуск. Во время управления
можно нажать Escape или перевести курсор в левый верхний угол экрана.
При распознанной капче повторяется выбранный звуковой сигнал; после ручного решения запуск завершается.

Неверная структура калибровки показывает предупреждение на новой вкладке, сохраняя доступность остальных
вкладок. Ошибочная неиспользуемая пауза проверяется тем этапом, которому она нужна; в редакторе её можно
исправить. Сохранение общих настроек требует корректности всех введённых значений.

Образцы и калибровка находятся в `data/desktop/`, исключённой из Git. Проверка URL и текста поля
временно использует буфер обмена и восстанавливает прежний **текст**; форматирование и другие форматы
буфера не сохраняются. Полные снимки рабочего стола не записываются: сохраняются выделенные фрагменты.
Поиск изображений зависит от оформления сайта и масштаба; после их изменения образцы нужно обновить.
[Схема экранного сценария](../Diagrams/desktop_applications.md). Живой прогон нового режима ещё не выполнен;
отсутствие капчи или блокировки не гарантируется.
