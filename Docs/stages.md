# Этапы обработки вакансий

[Краткий запуск](../README.md) · [Карта кода](architecture.md)

Все команды выполняются из корня проекта.

## Запуск этапов

В интерфейсе поля «Со строки» и «Лимит» действуют для заполнения по ссылкам, ИИ, отправки,
проверки ответов и сохранения HTML сайтов. «Со строки» можно оставить пустым: этап начнёт с первой
подходящей записи. Для заполнения это строка со ссылкой и пустым статусом; полностью пустые строки пропускаются.
Если номер указан, он задаёт нижнюю границу отбора — настоящий номер строки Google Таблицы, начиная с 2.
Для поиска и импорта HTML эти поля не применяются. Пустой лимит сохраняет прежнее поведение:
у ИИ используется `ai_max_rows` из общего JSON, у остальных этапов ограничение отсутствует.

Те же параметры доступны в консоли. Например, отправить **не более пяти новых подтверждённых откликов**,
начиная со строки 13:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py send --start-row 13 --limit 5
```

Отправляются только `done`. Уже отправленные отклики, архивы, анкеты и пропуски не расходуют этот лимит,
поэтому просмотр может пройти дальше строки 17. В итогах отдельно показано число новых отправок.
При капче или неизвестном результате отправки этап останавливается. В остальных режимах лимит ограничивает
число выбранных вакансий; ошибка или пропуск внутри выбранной очереди не добавляет новую строку сверх лимита.
Исключение — `requirements`: лимит считает попытки анализа, пропуская заполненные ключевые слова и пустые описания.

Только для проверки ответов есть отбор по **дате последней проверки**:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py check --checked-from 2026-11-10 --checked-to 2026-11-12 --limit 5
```

Обе даты включены целиком. В интерфейсе это поля «С» и «По»; можно заполнить одну границу.
Поля расположены в отдельном блоке «Только „Проверить ответы“: дата последней проверки» и не влияют на ИИ.
Чтобы выбрать давно не проверявшиеся вакансии, заполните «по». Пустые даты при заданном диапазоне
исключаются; галочка «Включать ещё не проверенные» или `--include-unchecked` добавляет их.
Неверные даты пропускаются с сообщением. Поддерживается ISO-текст `YYYY-MM-DD` или `YYYY-MM-DD HH:MM:SS`,
который сохраняет программа. Без диапазона дат все подходящие `wait` рассматриваются независимо от даты.

Например, заполнение строк по ссылкам запускается так:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py fill
```

Для другого этапа замените `fill` на режим из таблицы ниже. Справка:
`.\.venv\Scripts\python.exe -X utf8 Scripts\run.py --help`.

| Режим | Что делает | Что требуется |
|---|---|---|
| `import-html Examples\search.html` | Берёт ID, ссылку, название и компанию из сохранённой выдачи hh | HTML-файл и Google Таблица; Chrome не нужен |
| `import-folder Examples\search_pages` | Импортирует те же поля из всех HTML-выдач в выбранной папке | Папка HTML и Google Таблица; подпапки не читаются |
| `fill` | Дополняет строки со ссылкой и пустым статусом; ставит `new` | Chrome с hh и Google Таблица |
| `search` | Собирает ссылки из живой выдачи, читает новые вакансии; ставит `new` | `data/search_url.txt`, Chrome с hh и Google Таблица |
| `ai` | Готовит письмо, риски и оценку для `new`; ставит `done` либо `thinking` | Локальные настройки ИИ и Google Таблица; Chrome не нужен |
| `requirements` | Заполняет пустые ячейки `Ключевые слова` по описаниям любого статуса | Колонка `Ключевые слова`, модель, файл ключа и Google Таблица; резюме и Chrome не нужны |
| `send` | Проверяет `done` на hh и отправляет готовое письмо | Chrome с hh и Google Таблица; **отклик уйдёт работодателю** |
| `desktop-send` | Проба заполнения открытого окна; с `--submit` — реальная отправка по экрану | Обычный Chrome, Google Таблица и калибровка; отдельные зависимости |
| `check` | Проверяет ответы для `wait` и записывает `Дата проверки` | Chrome с тем же аккаунтом hh и Google Таблица |
| `collect-html` | Сохраняет HTML вакансий предприятий по ссылкам из таблицы | Chrome для новых URL, лист с `Ссылка` и `Статус`; таблицу не меняет |
| `import-results` | Добавляет готовые vacancy.json/draft.json в отдельный выбранный лист; дубли ID/URL пропускает | Google Таблица с колонками ИИ, папка снимков; без модели и Chrome. Лимит — новые записи |
| `draft-html` | По локальным vacancy.json готовит письмо, риски, оценку и специальные требования в draft.json | HTML-снимки, резюме, модель и ключ; без Google и Chrome |
| `process-html` | Распознаёт сохранённые HTML и создаёт `vacancy.json` | ИИ, папка снимков; без Chrome и Google. Лимит и необязательная папка `--data-dir` |
| `import-telegram result.json --channel https://t.me/channel_name` | Сохраняет текстовые посты из экспорта одного публичного канала | Локальный JSON; без сети, Google и ИИ. Лимит считает новые снимки |

Для Telegram используются те же `process-html`, `draft-html`, `import-results` с
`--data-dir data/telegram`; в интерфейсе папка передаётся автоматически. [Инструкция](telegram.md).

### Статусы вакансий в таблице

| Статус | Значение |
|---|---|
| пусто | Ссылка добавлена, сведения о вакансии ещё не заполнены |
| `new` | Сведения заполнены; письмо ещё не подготовлено |
| `done` | Письмо готово; отклик ещё не отправлен |
| `wait` | Отклик отправлен, ответ работодателя ещё не получен |
| `reject` / `invite` | Отказ / приглашение |
| `form` | Нужна ручная анкета или внешний сайт |
| `archive` / `unavailable` | Вакансия архивная / недоступна аккаунту |
| `thinking` / `no` | Нужна ручная проверка или пользователь обдумывает вакансию / решил не откликаться |

Обычная последовательность для сохранённой выдачи: `import-html → fill → ai → send → check`. Для живого
поиска команда `search` заменяет первые два этапа. `collect-html` относится к отдельному сценарию сайтов
предприятий; `process-html` распознаёт снимки, `draft-html` готовит локальные письма. `import-results` добавляет готовые результаты в отдельный выбранный лист. VPN или прокси между этапами
переключается вручную.

### Сохранить открытый поиск в HTML

В Chrome программы откройте нужную выдачу hh и оставьте её текущей вкладкой.
Выключите VPN перед обращением к hh. Для первой проверки сохраните две страницы:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\save_search_html.py --pages 2
```

Без `--pages` скрипт идёт до конца выдачи: использует «Дальше» или номерную ссылку на следующую страницу.
Он начинает с текущей страницы, не открывает поиск из файла настроек и не читает вакансии по отдельности.
HTML после подгрузки карточек сохраняется в `Examples/Examples_search_ДД_ММ_ГГ`,
по локальной дате компьютера при запуске. Свободные имена `sample_1.html`, `sample_2.html` и т. д.
сохраняют прежние файлы этого дня. Папка исключена из Git.
Используются существующие паузы поиска, проверки перехода и капчи. При капче или ошибке запуск останавливается;
готовые файлы остаются. Google Таблица и ИИ не используются.
Сохранённую папку затем можно передать кнопке «HTML из папки» или команде `import-folder`.

### Импорт сохранённой выдачи и поиск hh

Для `import-html` вручную откройте страницу поиска hh, дождитесь карточек и сохраните её текущий DOM в UTF-8
как `Examples/search.html`. Нужна выдача, не отдельная вакансия. Запуск:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py import-html Examples\search.html
```

Импорт не обращается к hh. Для новых ID он добавляет очищенную ссылку, название вакансии и компанию
обычным текстом. Отсутствующие в карточке название или компания остаются пустыми; повторный импорт
не добавляет дубли и не меняет уже существующие строки. Следующий `fill` заполняет данные в тех же строках. Строки с любым непустым статусом
`fill` пропускает, сохраняя ручные значения и формулы.

Для нескольких сохранённых страниц положите их в одну папку и выполните:

```powershell
.\.venv\Scripts\python.exe -X utf8 Scripts\run.py import-folder "Examples\search_pages"
```

В интерфейсе выберите «HTML из папки». Файлы `.html` и `.htm` читаются по имени, без подпапок.
Повторные ID объединяются до записи; при повторе дополняются только пустые название или компания
из первой карточки. Неподходящие и повреждённые файлы пропускаются с сообщением.
Если пригодных вакансий нет, подключение к Google не выполняется. Статус и дата добавления остаются пустыми до `fill`.
Импорт читает шапку и существующие ID один раз, затем добавляет партии до 50 строк одним запросом.
Между партиями по умолчанию пауза 5 секунд; её можно изменить в «Настройки → Паузы и ожидания»
(«между партиями HTML-импорта в Google Sheets»). Во время импорта не меняйте шапку листа.
При явном отказе `429` выполняются до четырёх повторов через 5, 15, 30 и 60 секунд.
Пауза сокращает нагрузку, но квоту могут расходовать и другие запуски с тем же доступом.
Сетевой обрыв и остальные ошибки останавливают импорт: результат последней партии нужно проверить.
Подтверждённые партии остаются в таблице; повторный импорт пропускает их по ID.
Нужны сохранённые страницы поисковой выдачи hh; HTML отдельных вакансий и сайтов предприятий сюда не подходит.

Импорт использует вставку `INSERT_ROWS`. Google определяет конец логической таблицы; пустой промежуток
может стать местом вставки, а прежние записи ниже сдвинутся. Импорт не заполняет подготовленные пустые
строки на месте. Ищите вакансию по ID, а не по прежнему номеру строки. Журнал показывает диапазон каждой записанной партии.

Для `search` запишите **одну** ссылку на нужную выдачу hh в `data/search_url.txt`. Число просматриваемых
страниц задаёт `PAGES_TO_SCRAPE` в `core/config.py`. Поиск пропускает известные ID и заголовки из `BLACK_LIST`;
существующие строки он не дополняет. Ссылки в сценариях hh очищаются от параметров, а зарплата сохраняется
текстом как на странице. Контакты HR пока не собираются.
Если стрелки «Дальше» нет, выбирается существующая номерная ссылка строго на текущую страницу + 1.
Конец выдачи — отсутствие обоих вариантов. Перед чтением и сохранением проверяются URL и активный номер
в разметке; у единственной первой страницы пагинация может отсутствовать.
Переход использует прокрутку Actions: кнопка поднимается выше нижнего края окна.
После существующей паузы кнопка и её адрес читаются заново, затем выполняется один обычный клик.
Если перекрытие остаётся, сбор останавливается с коротким сообщением без большого стека ошибки.
Эта общая функция используется и поиском, и сохранением HTML; длительности пауз сохранены.
Для проверки пагинации задайте `PAGES_TO_SCRAPE = 2` и проверьте переход со страницы 1 на 2.
Число страниц ограничивает сбор ссылок, а не последующее чтение найденных вакансий.
При переходе сверяются домен, путь и номер страницы; остальные поисковые параметры URL пока не сравниваются.

### Отправка и проверка ответов

`send` выбирает строки `done` и проверяет письмо каждой строки перед отправкой. Пустое письмо не отправляется.
Программа использует резюме, уже выбранное в окне hh, и перед отправкой сверяет состояние вакансии. Если
отклик уже виден на hh, повторного клика не будет. Когда
открывается анкета, программа её не заполняет: записывает `form` и ссылку в комментарий. Если поле письма
скрыто, нажимает «Добавить сопроводительное». Статус `wait` записывается после подтверждения отклика, а не
после одного клика. Письмо вводится блоками по 20 символов с паузами 0,4–0,8 секунды.
Между реально посещёнными вакансиями пауза 240–360 секунд; после последней строки ожидания нет.
После финального клика `hh/application_result.py` сохраняет прежнюю паузу, затем ждёт результат
на текущей странице до `APPLICATION_RESULT_TIMEOUT` (по умолчанию 20 секунд). Повторной загрузки
или клика нет. Подтверждением служит известный статус либо видимое «Резюме доставлено» в блоке отклика;
перед чтением проверяется ID текущей вакансии. Служебное окно выбора города не считается анкетой.

При неизвестном экране или сбое запись результата останавливается; `done` остаётся для повторного запуска.
Перед повтором программа снова проверяет hh. Если предыдущий отклик не виден на странице, повторная отправка
всё же возможна — сначала посмотрите отклики вручную. Одновременно запускайте только одного отправщика.

`check` открывает только строки `wait`. Он распознаёт ожидание ответа, отказ, приглашение, архив и
недоступность вакансии; после реального посещения записывает локальное время в `Дата проверки`. При
неизвестном результате прежние значения остаются. Если в старой таблице есть `Доступность = archive`, эта
отметка переносится в статус `archive` без открытия hh и без новой даты. `unavailable` означает ограничение
доступа, а не доказанный архив.

### Известные ограничения отправки

- Распознавание основано на предоставленных примерах разметки. Неизвестный экран не подтверждает
  отправку; после тайм-аута запуск останавливается. Ранее ошибочно выставленные `form` автоматически
  не исправляются: сверьте их с hh и поставьте `wait` вручную, если доставка подтверждена.
- Если капча появилась после финального клика, отклик мог уже уйти, но статус останется `done`:
  подтверждение результата и запись в таблицу ещё не выполнены. Перед повтором проверьте эту вакансию
  на hh вручную. Команда `check` выбирает только `wait` и такую строку автоматически не исправит.
- В лимит новых отправок входят только подтверждённые отклики. Если после клика результат неизвестен,
  этап останавливается: последняя отправка могла состояться, хотя ещё не учтена в итогах.

Чтение текущей страницы отделено от открытия вакансии; служебные окна не дают `form` только из-за
дополнительного поля. Локальные проверки пройдены, реальный прогон нового подтверждения ожидается.
Обработка капчи остаётся прежней.

### Сохранение HTML предприятий

Для `collect-html` выберите отдельную вкладку с колонками `Ссылка` и `Статус`. Добавьте полные URL
предприятий и оставьте статус пустым. Программа сохраняет текущий DOM в `data/vacancies/`, отдельно для
каждого полного URL. Параметры и фрагменты внешних адресов сохраняются; очистка ссылок hh здесь не
применяется.

Повторный запуск пропускает готовые снимки без открытия Chrome. Повреждённый снимок не перезаписывается.
Таблица и статусы остаются прежними. Динамические блоки, которые ещё не загрузились, а также содержимое
отдельных iframe и shadow DOM могут отсутствовать в сохранённом HTML.
[Схема сценария предприятий](../Diagrams/company_vacancies.md).
